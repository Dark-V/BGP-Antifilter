# Portainer: готовый образ и самостоятельный стек

Стек рассчитан на **Docker Standalone под Linux**. Сборка на Docker-хосте,
папка исходников и SSH не нужны. Вставьте `deploy/portainer-stack.yml` в
**Stacks → Add stack → Web editor**, назовите стек `bgp-antifilter` и задайте
`ADMIN_PASSWORD` в разделе Environment variables.

Исходные значения подготовлены для:

| Параметр | Значение |
| --- | --- |
| Docker-хост / BIRD / DNS-прокси | `192.168.88.10` |
| MikroTik | `192.168.88.1` |
| AdGuard | `192.168.88.16:53` |
| Панель | `http://192.168.88.10:8080` |
| Проверка DNS | `http://192.168.88.10:8053/ready` |
| Локальная AS / AS MikroTik | `64500` / `65455` |
| Синхронизация | `bird`, 1 секунда, `servfail` при ошибке |

Значения можно переопределить переменными стека; параметры DNS/BGP доступны
также в панели. AS и адреса должны соответствовать BGP-сессии MikroTik.
Готовность DNS при `HEALTHCHECK_REQUIRE_BGP=1` требует установленной внешней
BGP-сессии. `bird` подтверждает локальную таблицу BIRD, а не FIB MikroTik.

На адресе `192.168.88.10` требуются свободные TCP/UDP 53, TCP 179, 8080,
8053 и локальный TCP 1179. Стек использует сеть хоста, не задаёт шлюз,
`sysctl`, `privileged` или `NET_ADMIN` и не устанавливает маршруты в Linux.
Панель использует Docker-сокет для применения настроек своих сервисов.

Данные и SQLite сохраняются в именованном томе `generated`, сокет BIRD —
в `bird-run`. Манифест для применения настроек уже включён в образ: монтировать
каталог Git или файлы Compose с хоста не требуется. Не удаляйте тома при
обновлении. После отключения интеграции в панели повторное развёртывание
стека может создать контейнер DNS-прокси, но он останется без DNS/BGP-обработчиков
и открытых портов до включения интеграции.

Обновляйте **сам образ** через Portainer. Встроенное обновление приложения
отключено для такого развёртывания, а сохранение и применение настроек панели
работают. Для воспроизводимого запуска задавайте `BGP_ANTIFILTER_IMAGE` как
`ghcr.io/dark-v/bgp-antifilter@sha256:...`; тег `portainer` предназначен для
отслеживания новых сборок. Ссылка и digest готовой сборки выдаются вместе
с подготовленным стеком после проверки публикации в GHCR.

Настройка клиентов и автоматическое переключение DNS MikroTik описаны в
[adguard-dns.md](adguard-dns.md). Развёртывание стека не изменяет MikroTik или
настройки самого AdGuard.
